# 《首页 · 工作台》需求文档

> 关联文档：`00-产品总览与公共规则.md`（本文中术语、状态、字段不再重复定义，直接引用）

---

## 1. 模块目标

工作台是用户进入小程序后的第一个 Tab，定位为"AI 钢贸经营驾驶舱"，必须满足：

1. **身份明确**：3 秒内告诉用户"我是谁、当前在哪家企业、已开通多少 AI 服务"。
2. **服务直达**：核心 AI 服务一屏可达，已开通的优先展示。
3. **风险看得见**：所有子系统的风险预警在首页一键聚合，避免分散在各 AI 内。
4. **待办不漏**：跨子系统的待办在首页归集，点击直达对应业务页面。
5. **商城闭环**：未开通服务必须能在首页直接触达购买。

---

## 2. 页面结构总览

```
┌─────────────────────────────────────────┐
│ 顶部产品 LOGO + 名称 + 头像（点击进我的）│  ← 模块 A
├─────────────────────────────────────────┤
│ 用户问候卡（用户名 + 当前企业切换 +     │
│   已开通服务进度 + 购买入口）           │  ← 模块 B
├─────────────────────────────────────────┤
│ 核心服务（六宫格，2×3，含解锁状态）     │  ← 模块 C
├─────────────────────────────────────────┤
│ 风险预警（高/中/低/提醒 + 详情列表）    │  ← 模块 D
├─────────────────────────────────────────┤
│ 今日待办（跨子系统聚合）                │  ← 模块 E
├─────────────────────────────────────────┤
│ 底部 Tab                                │
└─────────────────────────────────────────┘
```

## 3. 模块 A · 顶部品牌区

| 元素 | 说明 |
| --- | --- |
| LOGO | 平台 LOGO 固定显示 |
| 名称 | "AI 钢贸小助理" |
| 副标题 | "智能化钢材贸易管理平台" |

**异常**：未登录 → 显示默认头像与"未登录"文案；点击头像直接拉起微信授权登录。

## 4. 模块 B · 用户问候卡

### 4.1 元素

| 元素 | 内容 | 交互 |
| --- | --- | --- |
| 问候语 | "尊敬的用户" | 文案固定 |
| 用户名 | 取自微信昵称或 ERP 关联姓名 | / |
| 当前企业 | 显示企业简称 + 下拉箭头 | 点击 → 跳转《我的 → 企业切换》 |
| 服务进度 | 已开通服务：`X / 6`（X 为已开通服务数，6 为平台总服务数，后端可配置） | / |
| 购买按钮 | "购买" | 点击 → 跳转商城首页（即《我的服务》带 `from=home_buy` 参数） |

### 4.2 业务规则

- **未登录**：用户名展示为"游客"；企业显示"未关联企业，去登录"；服务进度展示 `0 / 6`；点击任意元素均触发登录授权。
- **已登录但未加入企业**：企业位置显示"去关联企业 >"，点击跳转《企业切换》。
- **采购企业**：服务进度仍展示，但点击"购买"按钮时弹窗：`当前为采购企业，需升级为钢贸企业后才能开通 AI 服务，是否立即升级？`
- 服务进度数字需实时反映订阅状态变化（购买/到期/退款后 5 秒内更新）。

## 5. 模块 C · 核心服务

### 5.1 布局

- 2 列 × 3 行 共 6 个固定服务卡（S01～S06，见总览第 4 节）。
- 卡片元素：图标、服务名、状态标签（小字）。
- 已开通服务图标正常着色；未开通服务图标置灰且右上角带 🔒 小锁标识。

### 5.2 排序规则

| 优先级 | 规则 |
| --- | --- |
| P0 | **未登录**：按默认顺序展示一套（S01～S06） |
| P1 | **已登录**：已购买的服务优先排前，未购买的排后 |
| P2 | 新购买的服务追加到"已开通服务"末位（不顶替老服务位置，保持用户习惯位置） |
| P3 | 用户可在《设置 → 服务排序》中自由拖拽，**仅限已开通服务之间互换**，未开通服务保持其相对顺序 |

> 排序结果同时影响《首页》《我的服务》中"已开通"区域的展示顺序。

### 5.3 交互规则

| 点击对象 | 规则 |
| --- | --- |
| **已开通服务卡** | 1. 校验当前用户对该服务的权限（见总览 3.3）；<br>2. 有权限 → 进入该子系统首页；<br>3. 无权限 → Toast：`管理员及超管默认拥有权限，其他成员暂未授权，请联系企业管理员开通该服务/权限` |
| **未开通服务卡** | 进入该服务的"详情/购买"页：<br>- 若商城中存在该服务的独立 SKU → 进入该 SKU 详情页可直接购买；<br>- 若不存在独立 SKU（只在套餐中包含） → 进入商城列表，并自动定位至包含该服务的套餐 |
| **试用中服务** | 进入子系统首页，同时顶部出现"试用还剩 X 天，立即购买"横条 |
| **重磅推出** | 弹窗 `该服务即将上线，是否预约通知？`，确认后写入预约用户表 |
| **右上角"服务市场 >"** | 跳转《我的服务》商城首页 |

### 5.4 校验顺序

> 所有进入逻辑统一：登录态 → 企业关联 → 服务订阅状态 → 个人权限 → 跳转。

## 6. 模块 D · 风险预警

### 6.1 来源

- 列表由平台聚合，数据来自各核心服务（AI 库存/AI 出纳/AI 录入/提货宝/对账宝/钢贸征信）。
- 平台只做"列表与红点呈现"，详情页由对应子系统提供。

### 6.2 顶部数字卡

三色卡片显示当日未读未处理数量：

| 颜色 | 文案 | 含义 |
| --- | --- | --- |
| 红 | 高风险 X | `subType = 高风险` 的未处理数量 |
| 黄 | 中风险 X | `subType = 中风险` 的未处理数量 |
| 灰/蓝 | 提醒 X | `subType = 提醒` 或 `低风险` 的未处理数量 |

> 点击数字卡 → 跳转《消息 · 风险预警分类筛选页》（自动应用相应等级筛选条件）。

### 6.3 列表项

字段统一采用总览 6 章定义。单条列表项展示：

- 左侧颜色条（红/黄/灰）
- 标题（≤20 字，超出 …）
- 摘要（单行）
- 时间（今天 HH:mm / 昨天 / MM-DD）
- 右侧状态标签："未处理 / 已读 / 已处理"
- 红点：未读时显示

### 6.4 交互

| 行为 | 处理 |
| --- | --- |
| 点击列表项 | 进入该条预警对应子系统的详情页；子系统左上角面包屑：`< 返回 工作台` |
| 详情页返回 | 回到首页（而非子系统首页） |
| 详情页内"标记已处理" | 同步更新平台状态 |
| 右上角"查看全部 >" | 跳转《消息 · 风险预警分类页》 |

### 6.5 状态机

| 当前 → 目标 | 触发 |
| --- | --- |
| 未读未处理 → 已读未处理 | 用户进入详情页 |
| 已读未处理 → 已读已处理 | 用户在子系统点击"标记已处理" |
| 任意 → 已读已处理 | 在《消息》中长按 → "标记已处理" |

> 注：平台不允许直接由"未读"跳到"已处理"，必须先经"已读"，保证用户实际看过详情。

## 7. 模块 E · 今日待办

### 7.1 数据组成

- 由各核心服务（S01～S06）统一上报"待办"类型消息，平台做聚合展示。
- 字段、状态机沿用总览 6 章。
- 只显示**今日未处理 + 今日已处理**的条目；超过 24 小时仍未处理的待办自动转入《消息 · 待办》并标"超期"小红字。

### 7.2 行显示

```
[来源标签彩色徽标]  标题（≤20 字）         时间 HH:mm  >
                  摘要（单行 …）
```

- 来源标签按服务名简称：`对账 / 出库 / 入库 / 资金 / 库存 / 风险 / 征信 / 提货`
- 标签颜色映射服务主色（库存蓝、出纳绿、录入紫等）

### 7.3 交互

| 行为 | 处理 |
| --- | --- |
| 点击行 | 进入对应子系统的待办处理页；子系统左上角面包屑：`< 返回 工作台` |
| 完成处理 | 子系统回传状态，首页该行删除（带 0.2s 淡出） |
| 右上角"查看全部 >" | 跳转《消息 · 待办分类页》 |

## 8. 全局交互

| 交互 | 行为 |
| --- | --- |
| 下拉刷新 | 重新拉取：身份信息、订阅状态、风险预警、待办 |
| 上拉到底 | 风险预警、待办分别支持加载更多（首屏各 5 条，最多 20 条；超过引导去消息中心） |
| 长按列表项 | 弹出"标记已读 / 标记已处理 / 屏蔽该来源 7 天" |
| 网络断开 | 顶部显示橙色横条 "网络异常，点击重试" |

## 9. 数据接口约定（草案）

| 接口 | 用途 |
| --- | --- |
| `GET /home/profile` | 顶部身份卡数据：用户、企业、订阅进度 |
| `GET /home/services` | 核心服务及订阅状态（按排序规则返回） |
| `GET /home/risks?limit=5` | 风险预警聚合 |
| `GET /home/todos?limit=5` | 今日待办聚合 |
| `POST /home/services/order` | 服务排序保存 |
| `POST /risk/{id}/read` | 标记已读 |
| `POST /todo/{id}/handle` | 标记已处理 |

> 所有接口默认带 `enterpriseId` 上下文；切换企业后所有数据均重新拉取。

## 10. 异常与空状态

| 场景 | 文案 |
| --- | --- |
| 无任何风险预警 | 插画 + "今日风平浪静，继续保持！" |
| 无任何待办 | 插画 + "今日待办已清空，去看看 AI 帮你做了什么 >" → 跳转《消息 · 系统》 |
| 无任何已开通服务 | 核心服务卡片全置灰，底部 CTA："去商城开通你的第一个 AI 服务" |
| 当前企业为采购企业 | 风险预警与待办区域整体隐藏，替换为引导卡："升级为钢贸企业，开启 AI 经营管理" |

## 12. 验收清单

- [ ] 未登录态可正常浏览，所有受权限保护的入口均触发登录引导
- [ ] 已开通 / 未开通服务区分明显，未开通带锁图标

- [ ] 采购企业引导升级流程通顺
- [ ] 多企业切换后首页数据 5 秒内全量刷新
- [ ] 网络异常 / 接口异常 / 空状态文案与公共规则一致
