# 《消息》需求文档

> 关联文档：`00-产品总览与公共规则.md`

---

## 1. 模块目标

《消息》是平台的**统一通知与协作中心**，承担：

1. **聚合**：将各子系统的"系统通知 / 待办 / 待审批 / 风险预警"在小程序内一站式呈现。
2. **触达**：通过红点、订阅消息、模板消息确保用户不漏掉关键事件。
3. **协作流转**：点击即跳转对应子系统完成处理，回流状态同步。
4. **管理**：支持"全部标记已读""按来源屏蔽""分类筛选"等管理能力。

---

## 2. 页面结构总览

```
┌────────────────────────────────────────────┐
│ 顶部标题"消息"                              │
│ 右上 …  ← 操作菜单（标记全部已读/通知设置） │
├────────────────────────────────────────────┤
│ 分类 Tab：待办 ● │ 审批 ● │ 系统  │ 风险 ● │
├────────────────────────────────────────────┤
│ 当前分类的消息列表（分页/下拉刷新/长按操作）  │
├────────────────────────────────────────────┤
│ 底部 Tab                                    │
└────────────────────────────────────────────┘
```

> 分类 Tab 上的红点表示该分类下存在"未读"消息，红点不代表未处理（处理状态用"未处理"标签呈现）。

## 3. 分类设计

### 3.1 四个一级分类

| 分类 | 含义 | 数据来源 | 是否计入红点 |
| --- | --- | --- | --- |
| 待办 | 用户需要执行的业务操作（如签收、确认、补录） | 各子系统 | 是 |
| 审批 | 用户需要进行决策的审批流（如出库审批、付款审批） | 各子系统 | 是 |
| 系统 | 平台/子系统的状态/服务/订单/账户通知 | 平台 + 子系统 | 是 |
| 风险 | 高/中/低风险预警（首页风险预警的全量列表入口） | 各子系统 | 是 |

> 思维导图中将"待办"出现两次，按业务理解为"待办（业务待办）"与"审批（待审批）"两类，本文按上述四类划分。

### 3.2 二级筛选

每个一级分类内提供二级筛选条件：

| 一级分类 | 二级筛选 |
| --- | --- |
| 待办 | 全部 / 各服务来源（AI 库存 / AI 出纳 / 提货宝 / 对账宝 …）/ 仅未处理 |
| 审批 | 全部 / 各审批类型 / 仅待我审批 / 我已审批 |
| 系统 | 全部 / 平台公告 / 订单 / 发票 / 服务到期 / 安全 |
| 风险 | 全部 / 高风险 / 中风险 / 低风险（提醒） / 各服务来源 |

## 4. 列表项设计

### 4.1 通用字段（沿用总览第 6 节）

| 字段 | 显示 |
| --- | --- |
| 来源标签 | 彩色徽标（对账 / 出库 / 入库 / 资金 / 库存 / 风险 …） |
| 标题 | 主标题，最多 20 字，超出 `…` |
| 摘要 | 单行展示，超出 `…` |
| 时间 | 显示规则：今天 `HH:mm` / 昨天 / 前天 / `MM-DD` |
| 红点 | 未读时显示 |
| 状态标签 | "未处理" / "已读" / "已处理"（不同分类略有差异，见 4.2） |
| 右箭头 `>` | 暗示可点击查看详情 |

### 4.2 不同分类的状态标签

| 分类 | 状态标签 |
| --- | --- |
| 待办 | "未处理" / "已处理" / "已超期" |
| 审批 | "待我审批" / "已通过" / "已驳回" / "已撤回" |
| 系统 | "未读" / "已读" |
| 风险 | "未处理" / "已读" / "已处理"（沿用首页矩阵） |

### 4.3 已 / 未读与处理矩阵（与首页保持一致）

| 未读 | 处理 | UI |
| --- | --- | --- |
| 未读 | 未处理 | 红点 + "未处理" |
| 已读 | 未处理 | 无红点 + "未处理" |
| 已读 | 已处理 | 无红点 + "已读/已处理" |

### 4.4 排序规则

1. 未处理 > 已处理；
2. 同处理状态下，未读 > 已读；
3. 时间倒序（最新在上）。

## 5. 点击与跳转

### 5.1 点击列表项

- 触发"已读"状态变更（如本来未读，则即时变更为已读）。
- 跳转至对应子系统的详情页（通过 `deepLink` 字段）。
- 子系统详情页左上角面包屑：`< 返回 消息`。
- 在子系统中完成操作（处理/审批通过/驳回等）后，回到《消息》本页，对应行：
  - 状态标签更新为"已处理 / 已通过 / 已驳回"；
  - 若开启"自动隐藏已处理"则 0.3s 淡出。

### 5.2 跨平台跳转

| 来源 | 处理 |
| --- | --- |
| 微信订阅消息点击 | 拉起小程序 → 直接跳详情页（同 5.1） |
| 微信公众号模板消息 | 同上 |
| 桌面端 / Web 端推送 | 通过 universal link 跳详情 |

### 5.3 子系统首页 vs 详情页面包屑

| 当前位置 | 左上角面包屑 |
| --- | --- |
| 子系统详情页 | `< 返回 消息` 或 `< 返回 工作台` |
| 子系统首页 | `< 上一页 主页`（主页 = 子系统首页本身，对应"打开子系统首页"按钮） |

> 即：从消息跳过去 = 返回消息；从首页跳过去 = 返回首页。该上下文需由跳转方传递 `from` 参数。

## 6. 顶部操作菜单（右上 …）

| 菜单项 | 行为 |
| --- | --- |
| 标记当前分类全部已读 | 调 `POST /msg/mark-read-all?type=xxx`；列表所有红点立刻清除 |
| 标记全部消息已读 | 一次性清除所有分类未读 |
| 仅看未处理 | 切换筛选条件，本次会话内有效 |
| 通知设置 | 跳转《设置 → 通知管理》：勾选启用/关闭各类型的微信订阅消息 |
| 屏蔽来源管理 | 列出"已屏蔽来源"，可一键恢复 |

> 思维导图中"左上角添加面包屑-'点击显示全部已读'" 的语义已在本节"标记当前分类全部已读 / 标记全部消息已读"中实现。

---

## 7. 长按列表项菜单

| 菜单项 | 适用分类 | 行为 |
| --- | --- | --- |
| 标记已读 | 全部 | 单条置已读 |
| 标记已处理 | 待办 / 风险 | 不需要进入子系统直接关闭 |
| 标记待办（添加到首页待办） | 系统 / 风险 | 暂存到首页待办区 |
| 屏蔽该来源 7 天 | 全部 | 该来源消息 7 天内不再出现在 Tab/红点 |
| 删除 | 系统 | 仅"系统"分类可手动删除，删除即不可恢复 |

## 8. 风险预警分类详细规则

> 风险分类的列表，是首页风险预警区"查看全部 >"的目的页。

### 8.1 列表显示

- 顶部三色聚合卡（高/中/低）数量沿用首页样式；点击切换二级筛选。
- 列表项左侧色条：红/橙/灰。
- 标签：高风险/中风险/低风险/提醒。

### 8.2 详情页（在子系统中）

| 必含字段 | 说明 |
| --- | --- |
| 风险标题 | 同列表 title |
| 风险等级 | 高/中/低 |
| 来源 | 服务名 + 业务对象（如 `AI 库存 / 螺纹钢 HRB400 库龄超期`） |
| 触发时间 | `YYYY-MM-DD HH:mm` |
| 详情描述 | 多段，含数据 |
| 关联数据 | 表格 / 列表（如关联客户、单据） |
| 建议措施 | 由 AI 给出 |
| 处理操作 | "标记已处理 / 转待办 / 转交他人" |

### 8.3 状态机

| 当前 → 目标 | 触发 |
| --- | --- |
| 未读未处理 → 已读未处理 | 进入详情页 |
| 已读未处理 → 已读已处理 | 详情页内"标记已处理" |
| 已处理 → 未处理 | 暂不支持（如需复议须由子系统重新生成预警） |

## 9. 待办 & 审批分类详细规则

### 9.1 待办

- 来源：S01～S06 在业务流转中产生需用户继续操作的事项。
- 时效：默认 24 小时未处理打"已超期"红字标签，但仍出现在列表中（永不自动消失，除非被处理）。
- 操作：点击 → 子系统处理 → 回写状态。

### 9.2 审批

- 含义：业务流程节点需要本人决策。
- 字段补充：发起人、发起时间、当前节点、流程图入口。
- 操作：点击 → 子系统审批页（通过/驳回/转交/加签）→ 回写。
- 列表仅显示"待我审批"红点，已通过/已驳回历史可在二级筛选查看。

---

## 10. 系统分类详细规则

| 子类 | 触发 |
| --- | --- |
| 平台公告 | 运营在管理后台发布；可配置目标人群（全员/某企业/某角色） |
| 订单 | 下单、支付成功、支付失败、退款、关单 |
| 发票 | 申请、开具、寄出、邮件投递 |
| 服务到期 | 30 天 / 7 天 / 1 天 / 当日 / 到期后 多档提醒 |
| 安全 | 新设备登录、企业被切换、超管转让 |

> 系统通知不需要进入子系统，可在消息内直接展示完整内容（标题 + 详情 + 必要 CTA 按钮，如"去续费""查看订单"）。

---

## 11. 推送通道

| 通道 | 适用 |
| --- | --- |
| 微信小程序订阅消息 | 待办、审批、风险（高）、订单状态 |
| 公众号模板消息（可选） | 服务到期、对账完成、月报 |
| App 内消息 | 全量 |
| 短信（备用） | 高风险 + 用户未在 30 分钟内打开小程序时降级触达 |

> 推送通道由后端根据用户偏好（《设置 → 通知管理》）与消息类型组合决策；前端只负责接收与展示。

---

## 12. 全局交互

| 交互 | 行为 |
| --- | --- |
| 下拉刷新 | 拉取当前 Tab 最新数据 |
| 上拉加载 | 分页 20/页，最多滚动 500 条；超出建议用户使用筛选 |
| 切换 Tab | 立刻请求对应分类数据，缓存 30 秒 |
| 切换企业 | 整页刷新，所有数据按新企业上下文重拉 |
| 网络异常 | 列表保留缓存 + 顶部橙色"网络异常，点击重试" |
| 无任何消息 | 空状态插画 + 文案 + CTA "去工作台看看" |

## 13. 数据接口约定（草案）

| 接口 | 用途 |
| --- | --- |
| `GET /messages?type=&subType=&source=&handled=&page=` | 分类消息列表 |
| `GET /messages/unread-count` | 各 Tab 红点数量 |
| `POST /messages/{id}/read` | 标记单条已读 |
| `POST /messages/{id}/handle` | 标记单条已处理 |
| `POST /messages/mark-read-all?type=` | 整 Tab 已读 |
| `POST /messages/{id}/snooze` | 屏蔽来源 7 天 |
| `POST /notification-settings` | 通知开关配置 |

---

## 14. 异常与边界

| 场景 | 处理 |
| --- | --- |
| 消息引用的业务对象已被删除 | 详情页提示 `该业务对象已被删除或归档，无法查看` |
| 服务已到期，消息仍存在 | 列表项尾部追加灰色文案 `该服务已过期，续费后可处理` |
| 权限被收回 | 跳转拦截，提示 `您已无权处理该消息，请联系企业管理员` |
| 同一事件被多端处理 | 服务端做幂等，消息状态以服务端最终一致 |
| 时区 | 统一以企业所在城市时区显示 |

---

## 15. 埋点

| 事件 | 触发 |
| --- | --- |
| `msg_tab_view` | 切换 Tab |
| `msg_item_click` | 单条点击（带 type/source/id） |
| `msg_mark_all_read` | 标记全部已读 |
| `msg_long_press` | 长按操作（带动作类型） |
| `msg_subscribe_open` / `_close` | 订阅消息授权开关 |

## 16. 验收清单

- [ ] 长按菜单与分类的可选项匹配
- [ ] 从消息跳子系统后返回，回到消息且对应项状态同步
- [ ] 风险预警 Tab 与首页"查看全部 >" 入口一致
- [ ] 标题 20 字截断 / 摘要单行截断
- [ ] 服务到期、订单、安全通知均能正确推送并展示
- [ ] 切换企业后红点与列表同时刷新
- [ ] 通知设置页可关闭/开启各类型微信订阅消息
