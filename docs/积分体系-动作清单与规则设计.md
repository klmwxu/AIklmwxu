# 货袋子平台 · 积分体系动作清单与规则设计

> 适用范围：货袋子（钢贸 B2B SaaS）小程序 + 网页端
> 文档版本：v1.0
> 目标：以"个人积分 + 企业积分"双账户体系，驱动 **拉新（New User Acquisition）** 与 **活跃（Engagement / Retention）**，并为后续交易转化、生态共建沉淀用户行为数据。

---

## 1. 体系总览

### 1.1 双积分账户

| 账户类型 | 归属主体 | 主要用途 | 典型场景 |
|---|---|---|---|
| **个人积分**（Personal Points，PP） | 自然人账号（手机号 / 实名身份） | 个人激励，可在个人权益中心兑换：礼品、话费、视频会员、行业培训课程、平台增值服务体验券、抽奖券等 | 个人签到、个人分享、个人参与社区 |
| **企业积分**（Enterprise Points，EP） | 企业主体（统一社会信用代码） | 企业激励 + **企业会员等级评估依据**；由企业管理员在企业权益中心兑换：平台服务费抵扣、广告位、置顶资源、电子签章次数、仓储/物流优惠券、企业认证服务等 | 企业完成认证、企业首单、员工聚合活跃、企业拉新 |

> ⚠️ **重要：会员等级仅企业存在**。个人侧只有积分，不再设置会员等级；所有会员权益（积分倍率 / 服务费折扣 / 兑换折扣）的受益主体均为"企业"。

### 1.2 归属规则（重点）

为兼顾"个人激励"与"企业利益"，多数动作采用 **双发** 策略：

- **双发**：同一动作同时为个人和所属企业发放积分（金额可不同，例如 PP +10 / EP +5）
- **个人独发**：与企业经营无关的个人行为（如个人签到、个人完善资料）
- **企业独发**：仅与企业主体相关（如完成企业实名认证、企业首单、企业 SVIP 续费）
- **归属切换**：当员工离职 / 解除企业绑定时，已发放的个人积分保留在个人账户；企业积分留在企业。

### 1.3 设计原则

1. **目标对齐**：每一个动作必须能映射到「拉新」或「活跃」两个 OKR 之一。
2. **可量化、可监控**：所有动作必须可埋点，可还原归因链路（谁触发、谁受益、来源渠道）。
3. **有上限、防刷分**：每个动作设单日 / 单周 / 单月 / 终身上限，防止羊毛党与同一账号循环刷分。
4. **强转化导向**：核心激励（高积分）集中在 **企业入驻、实名认证、首单、复购、推荐企业入驻** 等关键 GMV 漏斗节点。
5. **轻量级动作低值高频**：签到、浏览行情等高频动作以 1~5 分小额激励维持 DAU。
6. **积分有效期**：个人积分有效期 12 个月（自获得日起），企业积分有效期 24 个月，过期清零，倒逼消耗。

## 2. 动作清单（核心交付物）

> 表头说明：
> - **动作编码**：用于埋点和后台规则配置（建议格式：`PT_类目_序号`）
> - **触发端**：小程序（MP）/ 网页（Web）/ 双端（ALL）
> - **触发条件**：业务上判定积分发放的精确条件
> - **个人积分 / 企业积分**：发放数值（建议初始值，正式上线前由运营进行 A/B 调参）
> - **上限**：单日 / 单周 / 单月 / 终身限制
> - **目标**：拉新（A）/ 活跃（R）/ 转化（C）

## 3. 防作弊与风控规则

| 规则编码 | 规则名称 | 说明 |
|---|---|---|
| AF_01 | **设备指纹去重** | 同一设备 24h 内最多触发 1 次注册类积分；多账号同设备注册不重复发放 |
| AF_02 | **IP / 手机号风险库** | 命中黑名单（虚拟号段、海外 IP、风险设备）不发放积分 |
| AF_03 | **行为时间间隔** | 浏览、签到等需有最小停留时间约束（如 ≥ 10 秒），秒退不计 |
| AF_04 | **拉新链路真实性** | 被邀人需完成「注册 + 实名 + 7 日内打开 ≥ 2 次」才计入有效拉新 |
| AF_05 | **企业邀请上限** | 单企业每月新邀员工 ≤ 100 人，单员工每月推荐企业 ≤ 5 家 |
| AF_06 | **交易类积分回收** | 订单退款 / 取消 / 仲裁失败 → 已发积分自动回收 |
| AF_07 | **撤销机制** | 内容被删除 / 违规 → 撤销已发积分 |
| AF_08 | **二级冻结** | 同一账号短时高频领分（如 1h 内 ≥ 30 个动作）→ 系统冻结待人工审核 |
| AF_09 | **实名门槛兑换** | 兑换权益必须完成实名 + 绑定手机号 |
| AF_10 | **企业积分仅企业管理员可使用** | 子账号不可消费企业积分，但可对企业积分有贡献度可视 |

## 5. 企业会员体系（4 级，仅企业）

> **设计意图**：与积分账户解耦，独立的"会员等级"是更易感知的身份标签；通过 **积分倍率 + 折扣率** 双杠杆撬动企业活跃与消费意愿。
> **作用主体**：仅企业；个人侧无会员等级。

### 5.1 等级总览

| 等级 | 编码 | 升级条件（任一满足即升级） | 积分倍率 | 服务费折扣 | 兑换商城折扣 | 等级有效期 |
|---|---|---|---|---|---|---|
| 普通会员 | **M1** | 完成企业认证即获得（默认） | **1.0×** | 无 | 无 | 长期 |
| 银卡会员 | **M2** | 滚动 12 月累计 EP ≥ **5,000**，或 年 GMV ≥ **100 万** | **1.2×** | **9.5 折** | 9.5 折 | 12 个月 |
| 金卡会员 | **M3** | 滚动 12 月累计 EP ≥ **30,000**，或 年 GMV ≥ **500 万** | **1.5×** | **9.0 折** | 9.0 折 | 12 个月 |
| 铂金卡会员 | **M4** | 滚动 12 月累计 EP ≥ **100,000**，或 年 GMV ≥ **2,000 万** | **2.0×** | **8.5 折** | 8.5 折 | 12 个月 |

### 5.2 升级逻辑

1. **评估口径：滚动 12 个月**
   - 每日 0 点重算企业账户的：滚动 12 月累计 EP（trailing_12m_ep）、滚动 12 月累计 GMV（trailing_12m_gmv）
   - 与 5.1 表中阈值比较，命中即触发升级
2. **升级时点：T+1 自动升级**
   - 任一指标首次达标 → 次日 0 点正式升级，APP 站内信 + 短信 + 邮件三连通知
   - 同步重置该等级的"有效期"（向后顺延 12 个月）
3. **直升通道（新企业冷启动）**
   - 新认证企业 **30 天内完成首单** → 直升 **银卡 M2**（试用 90 天）
   - 试用期满按常规口径评估；不达标自动回到 M1，且 6 个月内不再触发直升
4. **手工授级**
   - 平台 BD 可对战略客户、白名单企业进行人工授级（最高 M4），需要双人复核；记入审计日志

### 5.3 降级与保级逻辑

1. **保级提醒（到期日前 60 天启动）**
   - 系统进入"保级倒计时"，展示距离当前等级保级所需缺口（缺多少 EP / 缺多少 GMV）
   - 每周一次 APP 通知 + 提供运营推荐任务（如限时 EP 倍率活动）助力保级
2. **降级条件**
   - 等级到期日 0 点：若 EP 和 GMV **两个指标均不满足当前等级**，则降一级（如金卡 → 银卡，不会一次降两级）
   - 满足当前等级但已不满足上一级（仅适用于历史超额升级）→ 维持当前等级
3. **二次评估（兜底机制）**
   - 被降级后 **30 天内**，若任一指标重新达标 → 自动恢复原等级，一年内最多 1 次
4. **强制降级（风控）**
   - 企业被风控冻结 > 30 天，或一年内违规处罚 ≥ 3 次：强制降至 **M1 普通会员**
   - 强制降级后 90 天内不能通过普通升级路径回到原等级（人工授级除外）

### 5.4 积分倍率（multiplier）规则

| 维度 | 说明 |
|---|---|
| 作用对象 | 仅作用于**企业积分 EP** 的获取动作（参见 §2 动作清单全部带 EP 数值的动作） |
| 不作用对象 | 个人积分 PP、积分消耗（兑换不打折，受 5.5 折扣率影响） |
| 计算公式 | 实际入账 EP = 基础 EP × 当前会员倍率 × 活动倍率（取最大值，不叠加） |
| 取整 | 向下取整（floor） |
| 与限时活动叠加 | **不叠加**，取最大值（如会员 1.5× vs 活动 2.0×，按 2.0× 入账） |
| 与企业子账户关系 | 倍率作用于"双发"动作中 EP 那部分；个人 PP 部分不受影响 |

**示例**：
- 金卡企业的员工"发布资源"（基础：PP +15、EP +15）→ 个人 PP 仍 +15，企业 EP +15 × 1.5 = **+22**
- 铂金企业完成首单（基础：EP +1000）→ 实际 EP +1000 × 2.0 = **+2000**

### 5.5 折扣率（discount）规则

| 折扣类型 | 适用 | 说明 |
|---|---|---|
| **服务费折扣** | 平台佣金、电子签章包、信用查询次数、增值服务订购 | 结算时自动扣减 |
| **兑换商城折扣** | 企业积分商城所有商品/权益 | 标价 EP × 折扣率向上取整 |
| **不参与折扣** | 第三方代收款（保理利息、票据贴现）、合作品牌联名权益、限时秒杀商品 | 系统侧白名单 |

**示例**：
- 金卡企业兑换"首页 Banner 7 天"（标价 80,000 EP）→ 实际消耗 80,000 × 0.9 = **72,000 EP**
- 铂金企业月度结算服务费 ¥10,000 → 实际结算 ¥10,000 × 0.85 = **¥8,500**

### 5.6 会员权益矩阵（除倍率/折扣外的"软权益"）

| 权益 | M1 普通 | M2 银卡 | M3 金卡 | M4 铂金卡 |
|---|---|---|---|---|
| 月度免费置顶位 | 1 个 | 3 个 | 8 个 | 不限 |
| 广告位采购折扣 | — | 9.5 折 | 8 折 | 6 折 |
| 行业研报订阅 | — | 月报 | 月报 + 周报 | 全部 + 定制 |
| 电子签章次数（月赠） | 5 次 | 20 次 | 50 次 | 200 次 |
| 专属客服 | — | 5×8 群 | 7×12 群 | 1v1 专属 |
| 专属 BD | — | — | — | ✓ |
| 首页推荐 | — | — | 季度 1 次 | 月度 1 次 |
| 年度峰会席位 | — | — | 1 席 | 3 席 |
| API / ERP 联调支持 | 自助文档 | 自助 + 工单 | 工程师协助 | 驻场支持 |

### 5.7 数据模型（建议）

```
membership_tier
  ├── tier_code          (M1 / M2 / M3 / M4)
  ├── tier_name          (普通会员 / 银卡 / 金卡 / 铂金卡)
  ├── ep_threshold       (升级所需滚动 12 月累计 EP)
  ├── gmv_threshold      (升级所需年 GMV，单位：元)
  ├── point_multiplier   (1.0 / 1.2 / 1.5 / 2.0)
  ├── service_discount   (1.0 / 0.95 / 0.90 / 0.85)
  ├── mall_discount      (1.0 / 0.95 / 0.90 / 0.85)
  ├── benefits           (JSON，软权益清单)
  └── valid_months       (有效月数，M1 永久)

enterprise_membership   ← 企业当前会员状态
  ├── enterprise_id
  ├── current_tier       (M1~M4)
  ├── upgrade_at         (本次升级时间)
  ├── expire_at          (本次有效期到，M1 为空)
  ├── trailing_12m_ep    (实时滚动指标，每日刷新)
  ├── trailing_12m_gmv
  ├── protect_window_start (保级倒计时开始日，到期前 60 天)
  ├── source             (normal / probation / manual / recover / forced)
  └── status             (active / probation / frozen / expired)

membership_history      ← 完整升降级历史，用于审计与年度总结
  ├── enterprise_id
  ├── from_tier / to_tier
  ├── change_at
  ├── reason             (auto_upgrade / probation_pass / probation_fail / risk_force / manual)
  └── operator           (system / BD姓名)
```

### 5.8 关键接口（建议）

- `GET  /membership/enterprise/{id}`：返回当前等级、有效期、滚动 12 月指标、距下一级缺口
- `POST /membership/evaluate`：日终批跑，触发全量重算（运维使用）
- `POST /membership/manual-grant`：人工授级，双人复核
- `GET  /membership/benefits/{tier}`：返回该等级所有权益清单
- `POST /points/grant`：发放 EP 时，服务端自动读取企业当前 `point_multiplier` 计算实际入账数值
- `POST /points/consume`：消费 EP 时，服务端自动读取 `mall_discount` 计算实际扣减

### 5.9 风险与放权

| 风险 | 说明 | 应对 |
|---|---|---|
| 倍率刷单 | 企业为升级铂金会员，员工虚假交易刷 EP | EP 计入"滚动 12 月"时只计入已结算且超过 30 天无退款的订单 |
| 临时升级套利 | 短期冲量升级后立即降级 | 等级有效期 12 个月；降级 90 天内不可走普通路径恢复 |
| 折扣穿透 | 把会员折扣传给非会员 | 折扣只在企业账户结算时生效，购买主体校验 |
| 倍率叠加歧义 | 会员倍率 × 活动倍率 | 明确"取最大值，不叠加"，前端文案显著提示 |
| 财务负债通胀 | 高倍率扩大积分负债 | 月度财务复盘，必要时下调倍率（提前 30 天预告） |

## 6. 兑换商城（积分出口）

> "出口"决定"入口"的价值感，是积分体系是否能持续运转的关键。

### 6.1 个人积分（PP）兑换示例

- 话费 / 视频会员 / 京东 E 卡
- 行业报告（钢联 / Mysteel 联名）解锁
- 在线培训课程
- 实体礼品（保温杯、安全帽、笔记本等钢贸场景礼品）
- 抽奖券、限时插队权
- 钢贸节年会门票

### 6.2 企业积分（EP）兑换示例

- **平台服务费抵扣**：1000 EP = 1 元抵扣（仅限服务费、广告费、电子签章费等）
- 资源置顶位 / 首页 Banner 广告位
- 电子签章次数包
- 仓储 / 加工 / 物流优惠券（与服务商联合补贴）
- 信用报告查询次数（接入企查查 / 天眼查）
- SVIP 升级抵扣
- 年度行业峰会赞助席位

## 7. 风险与放权策略

| 风险点 | 应对策略 |
|---|---|
| 通货膨胀（积分发太多无处用） | 上线前需先建好兑换商城；积分有效期 12~24 月；月度财务结算积分负债 |
| 拉新作弊 | 邀请链路绑定设备指纹 + 7 日激活门槛 + 风控规则 AF_04 |
| 企业管理员独占 EP | 引入"贡献度看板"，员工对企业积分贡献排行；企业积分消费需经管理员审批，重大消费需董事 / 法人确认 |
| 离职员工 PP 流失 | 个人积分跟随个人，离职后保留；离职前 30 天通知 |
| 积分通胀冲击 GMV | 限定 EP 抵扣比例上限（如单笔订单服务费最多抵 30%） |
| 客观财务计量 | 积分按公允价值确认负债（参考会计准则 IFRS 15 / 收入相关条款） |

## 8. 上线节奏建议（仅描述阶段，不含日历估算）

- **阶段 1：基础闭环**
  - 上线动作：注册、实名、签到、分享、企业认证、首单、邀请同事
  - 上线出口：个人商城（话费 / 京东卡）+ 企业积分抵扣服务费
  - 上线管理后台：积分规则配置、积分流水、人工调整

- **阶段 2：行为引导**
  - 上线动作：成长任务、UGC、行情订阅、限时任务、企业聚合积分
  - 上线出口：抽奖、置顶位、增值服务券

- **阶段 3：交易深化**
  - 上线动作：交易阶梯返积分、物流仓储加工选用、电子签 / 发票、供应链金融
  - 上线出口：企业 SVIP / 战略伙伴等级权益

- **阶段 4：生态共建**
  - 推荐外部钢厂 / 仓库入驻、行业活动、深度访谈、合作伙伴联合营销

## 9. 数据看板与运营指标（KPI）

- **拉新指标**：新增注册数、邀请人均拉新数、被邀人 7 日留存、被邀企业认证转化率、被邀企业首单转化率
- **活跃指标**：积分用户 DAU/MAU、签到率、连续签到 7+ 天比例、人均触发积分动作数
- **企业活跃**：MAU 企业数、企业月均活跃员工数、企业月均发布资源 / 求购数
- **健康度**：积分负债余额、积分消耗率（兑换 ÷ 发放）、过期积分比例、积分人均成本
- **风控**：异常账号占比、积分回收率、规则命中率

> 经验阈值（行业平均）：积分消耗率应稳定在 30%~60%，过低（< 20%）说明出口太少，过高（> 80%）说明发放保守或通货紧缩。

## 11. 附录 B：典型链路案例（用于研发对接）

### 案例 1：员工分享小程序 → 拉新

```
[张三（A 企业员工）]
   │  点击小程序"分享给好友"，生成专属海报（含 invite_code）
   ▼
[李四（潜在客户）] 通过海报扫码进入小程序
   │  完成手机号注册 → 系统记录 invite_code = 张三
   ▼
积分发放：
  - 张三个人积分 +30（PT_AC_01）
  - A 企业积分 +10（PT_AC_01）

继续：李四在 7 日内完成实名 → 张三个人 +50 / A 企业 +20（PT_AC_02）

继续：李四所在 B 企业 60 日内完成入驻认证
  → 张三个人 +500 / A 企业 +300（PT_AC_03）
  → 同时给 B 企业 +300（PT_ON_07）

继续：B 企业 90 日内完成首单
  → 张三个人 +1000 / A 企业 +500（PT_AC_04）
  → 同时给 B 企业 +1000（PT_TR_04，企业首单）+ B 企业员工首单负责人 +100
```

### 案例 2：企业完成认证 → 首笔交易

```
[A 企业法人] 提交营业执照 → +50 EP（PT_ON_06）
[平台审核通过] 营业执照 OCR + 对公打款验证通过 → +300 EP（PT_ON_07）
[绑定银行账户] 打款验证 → +100 EP（PT_ON_10）
[企业员工发起询价] +5 PP / +5 EP（PT_TR_01）
[卖方报价] +5 PP / +5 EP（PT_TR_02）
[生成线上合同（电子签约）] +20 PP / +50 EP（PT_TR_03）
[订单结算（平台对公）] +10 PP + 0.5‰ 金额 / +20 EP + 1‰ 金额（PT_TR_05）
[企业首单（仅首次）] +100 PP / +1000 EP（PT_TR_04）
```

### 案例 3：行情订阅 → 用户活跃

```
[用户进入行情中心] +1 PP（PT_RE_04）
[订阅"螺纹钢 + 华东"组合] +20 PP（PT_RE_09）
[7 日内保持订阅，平台推送 5 条行情] 用户连续打开 → 触发签到（PT_RE_01）
[累计 7 日签到] +10 PP（PT_RE_02）
```

## 12. 后续待办（建议）

1. 运营复盘机制：每季度对积分发放 / 消耗、负债余额进行复盘，淘汰低 ROI 动作、加码高 ROI 动作。
2. AB 测试：对高敏感动作（PT_AC_03/04、PT_TR_04）做不同积分系数的 AB，找到 GMV 拉动最优解。
3. 算法推荐：高积分用户优先曝光资源、优先匹配询报价，形成正循环。
4. 企业管理员视角的"积分仪表盘"：让企业老板看到员工贡献排行，加强企业内 viralCoefficient。
5. 与 CRM / 渠道 BD 系统打通：BD 看到推荐线索 + 邀请人积分链路，便于人工跟进。
